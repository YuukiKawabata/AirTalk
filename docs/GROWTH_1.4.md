## 2. 1.4の変更内容・採用計画

旧グループ中心案を置き換える。既存のオフライン無料機能と会話自動消去を維持し、任意のすれ違いから、相手を選び双方承認してオンライン1対1会話へ進める。
双方が「また話したい」を選んだ場合のみ接続関係を保持。恋愛専用・ランダム自動接続は初版対象外。

| 段階 | 内容 | 概算 | 状態 |
|---|---|---:|---|
| A / P0 | バックグラウンドBLE検出の実機試作と電池計測 | 3〜5人日 | コード・手順作成、実機待ち |
| B / P0 | オンライン・安全性・データ・運営費の設計 | 2〜4人日 | 実機を待たず設計・ローカル画面を先行。サービス接続条件は承認待ち |
| C / P1 | プロフィール、24時間すれ違い、申請・承認、会話、相互接続、通報／ブロック | 10〜15人日 | 未実装 |
| D / P0 | 日英、デモ、ビルド、実機、限定した場で検証 | 4〜6人日 | 未実施（Aの画面のみ日英デモ対応） |

全体暫定19〜30人日。待ち時間・継続運営は別。グループ、ブラウザ参加、買い切り、公開ルームは後回し。
既存Paywallのトライアル資格判定・通信状態修正は品質改善の候補として維持するが、今回のBLE試作には混ぜない。

### 段階Aの実装境界

- `#if DEBUG` と `-encounterPrototype YES` で内部検証画面を有効化。さらに画面の明示的な同意が必要。
- 専用画面では既存Multipeer探索とStoreKitの商品取得を起動しない。BLEだけを測定する。
- 同意後の有効フラグはローカル保持。OSの状態復元による起動では引数がなくても復元できる。オフで探索・広告・接続を停止。
- Debugのみ `Config/EncounterDebug-Info.plist` の bluetooth-central / bluetooth-peripheral を使用。Releaseは元のInfo.plistで、試作サービス・画面をコンパイルしない。
- 専用サービスUUIDをフィルタして探索。重複広告通知なし、通常同時接続2件まで、低電力時1件まで。読み取りを8秒で打ち切る。
- 同一BLE端末への再接続抑制は通常5分、低電力15分。OSが重複通知を抑制するため、再検出や定期読取りを保証しない。
- GATTの動的readでバージョン1＋ランダムUUID（17 bytes）だけを読む。人物情報・RSSI・位置・メッセージ本文は保存しない。
- ローカルトークンは15分経過後の次回動作／read時に更新。タイマーによる定時起床や15分ごとの再発見は行わない。
- この試作のGATT交換は未認証・未暗号化。再送・偽装・近接性を証明しない。協力者のテスト端末のみで利用する。オンライン本人識別に転用しない。
- 記録は一時UUID＋初回／最終検出日時のみ、端末のUserDefaultsへ最大200件。初回から24時間後の次回読出し／動作時に削除。停止中・OS停止中の壁時計どおりの物理削除は保証しない。
- UserDefaultsはバックアップ対象になり得る。自動バックアップを含む厳密な消去保証はなく、実ユーザー向け保存方式は段階Bで再設計する。
- カウンターはプロセス内のみ。起動／成功／失敗／バックグラウンド成功の状態を画面で確認する。人数・移動経路・距離を推定しない。
- サーバー／分析送信／公開プロフィール／通知／課金は追加しない。既存Releaseのプライバシー宣言は変更しない。

### 段階Bで承認する事項

アカウント方式、費用上限、保存データ、ログ・バックアップ・削除、通信暗号化、識別子更新・再送防止、年齢方針、通報証拠と利用停止、オンライン切断時の消去ルール。
サーバーなし／収集なしはオンライン部分について見直す。通常会話を残さない方針を維持し、通報証拠の例外は明示的に設計する。
プロフィール公開とすれ違い記録は任意同意。正確な位置・時刻・回数・移動経路は相手に表示しない。

## 4. 効果の見方・実機チェックリスト

### 実行方法

1. XcodeでAirTalkスキームのRunをDebugにする。
2. Arguments Passed On Launchに `-encounterPrototype YES` を追加し、協力者のiPhone 2台へビルドする。
3. 検証画面で説明を読み、両方の「すれ違い検出」をオン。Bluetooth権限を許可。
4. デバッガを切り離してテストする（デバッガ接続は停止・復元・消費に影響する）。
5. 各条件の開始／終了時に成功・背景成功・失敗・記録数を控える。時刻は観測側の記録。
6. 終了時は両端末ともオフにし、記録を消去。通常アプリへ戻すには起動引数を外して再起動。

既存スクショパイプラインでも `ENCOUNTER_PROTOTYPE=1 ./docs/capture-screenshots.sh` で日英・iPhone/iPadの試作生画像を追加できる（ストアパネルには含めない）。

シミュレータは画面確認のみ。Debugの `-demo YES -demoScene encounters` で架空データを表示できる。

### 電池測定

- 同一機種・OS・バッテリー状態・画面設定・通信状態で、試作画面の検出オフ／オンを各8時間、順序を入れ替えて3組比較。
- デバッガは外し、画面ロック、充電なし、同じ場所・周囲端末数を揃える。通常アプリのレーダー探索と混ぜない。
- 開始／終了残量、経過時間、発熱、成功／失敗、OS設定のバッテリー表示を記録。追加消費はオンとオフの差（percentage points / 8h）。
- InstrumentsのEnergy測定も補助に使うが、接続した測定と非接続の消費比較を分ける。
- 初期判断目安: ロック同士の2分滞在で各端末80%以上の検出、追加消費の中央値3ポイント/8h以下、継続発熱なし。製品保証値ではなく仮の進行基準。短いすれ違いは別途結果を示す。
- 端末・OS・実測値が揃うまでは段階A完了／本実装可能とは判定しない。
